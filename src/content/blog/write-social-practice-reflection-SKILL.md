# 社会实践心得写作

## 核心规则

撰写真实可信的学生心得，而不是研究论文。保持工作流独立，不依赖任何特定文献数据库、浏览器、VPN、连接器或下载技能。可以使用用户提供的 PDF、参考文献条目、实践笔记，或当前任务中通过可用工具取得的资料。

## 工作流程

### 1. 提取作业要求

开始写作前，完整阅读用户提供的通知、评分标准、模板、守则和示例，并记录：

- 必须使用的标题及排列顺序；
- 各部分和正文总字数的最低与最高限制；
- 参考文献的数量和类型要求；
- 引文格式、纸张大小、字体、页边距、打印方式和重复率限制；
- 必须使用的模板、实践日志、介绍信、签名或其他提交附件。

区分“正文内容要求”和“最终提交要求”。如果缺少指定模板或附件，先按照用户要求生成独立文稿，不得虚构缺失材料，并在交付时明确提示。

### 2. 建立事实清单

将信息分为四类：

1. 用户已经确认的事实；
2. 由附件或可靠资料确认的事实；
3. 可以提出但必须写成个人思考或改进建议的分析；
4. 尚未确认、因此不得写入的内容。

不得虚构实践日期、累计时长、人物姓名、现场对话、使用过的系统、承担过的职责、取得的成绩、地方政策，或未解释项目名称的具体含义。除非已经得到确认，不得暗示研学参观的技术已在学生的实际岗位中投入使用。正文中不得出现个人敏感信息。

### 3. 设计文献方案

选择一条能够串联全部实践活动的主线，避免把不同经历写成彼此无关的小文章。围绕下列方面建立若干简短的关键词组：

- 岗位和日常工作；
- 涉及的人群或公共服务问题；
- 可以联系的思想政治理论；
- 与实践有关的数字化、法治、伦理、安全或创新问题。

按照论证用途分配参考文献。优先选择内容易懂、能够直接支撑学生观察的资料，避免使用会迫使心得变成专业论文的高技术性文献。

取得原始文献后，从文献本身核对作者、题名、期刊、年份、卷号、期号和页码。不得编造参考文献信息。确保参考文献表中的每一条文献都在正文中实际引用。

### 4. 从实践经历向外展开写作

严格使用作业要求规定的标题。除非评分标准另有规定，实践经历和个人感受可占正文约 65%—75%，理论与文献可占约 25%—35%。

按照以下顺序展开：

1. 学生实际做了什么或看到了什么；
2. 哪些内容令人感到困难、意外、重复或不理解；
3. 从中发现了什么问题；
4. 课程理论如何帮助解释这个问题；
5. 可以提出什么适度的改进建议或个人行动。

使用与学生年级相符的第一人称表达。适当承认自身知识和能力的局限。优先使用“我当时以为……后来发现……”等自然转折，避免使用没有必要的“本文认为”“构建机制”“研究结果表明”等论文式表达；仅在概括或引用文献时使用学术表述。

把理论和具体经历联系起来。可使用的理论视角包括马克思主义实践观、以人民为中心的立场、群众路线、矛盾分析方法、法治思维、创新驱动发展和青年责任。不得只堆叠理论口号而不解释其与岗位实践的关系。

### 5. 让表达更像真实经历

以真实、自然、易读为目标进行修改，不以规避检测工具为目标。AI 检测结果存在波动，不得承诺任何固定比例。

减少：

- 各部分长度过度对称，以及反复使用“首先、其次、最后”的结构；
- 密集的抽象名词、口号，以及每段都高度完整的总结句；
- 过多的排比、破折号、引号和模板化过渡句；
- 暗示学生已经解决制度性问题的夸大表述。

仅在事实已经确认时增加：

- 来自实际任务的小观察；
- 学生的疑惑、认识变化和角色局限；
- 长短不同的句子和普通自然的连接词；
- 学生确实能够实施的后续行动。

不得为了让文字“像真人”而编造故事或现场细节。

### 6. 排版前进行校验

分别统计每个必需部分和全文正文的中日韩统一表意文字字符数。除非作业要求另有说明，参考文献不计入正文字数。

检查：

- 每一项最低字数均已达到，且没有超过最高字数；
- 必须使用的标题完整且文字准确；
- 参考文献数量符合要求；
- 每一条顺序编码参考文献都至少在正文中引用一次；
- 正文引文编号与参考文献表编号一致；
- 正文不存在个人敏感信息或未经证实的事实；
- 整体语气属于心得体会，而不是研究论文。

### 7. 生成 DOCX

如果学校提供正式 DOCX 模板，应直接修改该模板并保留其原有样式。如果没有正式模板，则使用 JSON 规格文件调用 `scripts/build_reflection_docx.py`。调用前先阅读 `references/input-format.md`。

运行：

```powershell
python scripts/build_reflection_docx.py input.json --output reflection.docx
```

脚本会先校验各部分字数、全文长度、参考文献数量及引文覆盖情况，然后生成 A4 DOCX，设置中文字体、分级标题、参考文献悬挂缩进和页码。

### 8. 检查交付文件

使用当前环境中可用的本地工具打开或渲染最终 DOCX。检查页数、空白页、落在页尾的孤立标题、内容重叠、字体替换、页码以及最后一页参考文献。通过程序重新打开 DOCX，确认文件没有损坏。

将文件复制到用户指定目录时，核对文件数量和哈希值。不得覆盖正在打开的文档；必要时创建名称清晰的新版本，例如 `_压缩版` 或 `_自然表达版`。

## 交付摘要

仅报告对用户有用的信息：

- 输出文件路径；
- 各部分和正文总字数；
- 参考文献数量及引文覆盖数量；
- 用户仍需补充的正式模板、日志、日期、实践时长、签名或其他附件。

不得声称能够保证固定的重复率或 AI 检测比例。
